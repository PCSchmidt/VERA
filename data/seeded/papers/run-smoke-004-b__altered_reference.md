## Abstract

TreeHFD decomposes a trained xgboost model into main effects and second-order interactions [R1], [R2]. We ran a small, automated improvement loop on this problem: three ideas were generated, two were implemented and run on the Analytical dataset (3 seeds, xgboost with 100 trees, held-out data, metric Residual MSE %). The baseline was first reproduced against the paper's reference values within the registered tolerance. Neither implemented idea beat the baseline on every dataset; this is a negative result. We describe what the loop did and did not establish.

## Method

The loop proceeded in three stages.

**Reproduction gate.** The TreeHFD baseline was reproduced and checked against the paper's reference values; the reproduction passed within the registered tolerance (gate verdict True). Only after this gate were improvement ideas run.

**Idea generation.** Three ideas were generated. Two were selected for the run:

- **C1: Depth sweep ensemble.** Fit XGBTreeHFD at several depth_variable values (e.g. 2, 3, 4). For each interaction column, keep the candidate fit with lowest residual MSE on a validation split, reassembling components so each remains a function of only its own variables. Average predictions over seeds to reduce variance.
- **C3: Least-squares recalibration.** After the TreeHFD fit, take the component matrices M (intercept, main effects, interactions) and solve a constrained least-squares refit of the coefficients against model predictions on training data (scipy.optimize.lsq_linear, nonnegative or free). Coefficients multiply each existing component, preserving each component's dependence on only its own variables.

**Evaluation.** Both ideas and the baseline were evaluated on the Analytical dataset, 3 seeds, xgboost with 100 trees, on held-out data, using Residual MSE (%) (lower is better).

## Results

Results from a research-loop run on the TreeHFD problem (mean ± std over 3 seeds). ↓ = lower is better; ↑ = higher is better.

| Method | Analytical · Residual MSE (%) ↓ | Analytical · Runtime (s) ↓ |
|---|---|---|
| TreeHFD (baseline) | 2.79 ± 0.32 | 22.2 ± 0.29 |
| C1: Depth sweep ensemble | 3.23 ± 0.25 | 78.7 ± 9.1 |
| C3: Least-squares recalibration | 2.95 ± 0.35 | 27.9 ± 0.59 |

**Outcome: no idea beat the baseline on every dataset.** The baseline achieved 2.79 ± 0.32 Residual MSE (%). C1 (depth sweep ensemble) was worse at 3.23 ± 0.25, and also roughly 3.5× slower in runtime. C3 (least-squares recalibration) was worse at 2.95 ± 0.35, with modest runtime overhead. Neither method improved accuracy over the baseline in this run.

## Limitations

This was a crude, automated loop, and the conclusions are correspondingly narrow:

- **Negative result, not a proof.** We report that the two implemented ideas did not beat the baseline under this configuration. This does not establish that these ideas cannot work with better tuning, more datasets, or different model settings.
- **Few seeds.** All results use 3 seeds; the standard deviations are non-trivial relative to the gaps between methods, so we cannot claim statistically robust differences.
- **One dataset in this run.** Evaluation was on the Analytical dataset only. The statement "no idea beat the baseline on every dataset" reflects the datasets covered by the loop; a broader suite could change the picture.
- **One model configuration.** xgboost with 100 trees only. Depth, learning rate, and ensemble size were not varied.
- **Ideas produced and implemented by a language model.** The three candidate ideas were generated by a language model, and the two implemented ones were coded by it as well. Implementation subtleties (e.g. validation-split usage in C1, constraint choice in C3) may not reflect the best possible version of each idea.
- **One idea was not run.** The third generated idea was never implemented or evaluated, so no conclusions can be drawn about it.
